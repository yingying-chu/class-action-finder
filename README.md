# Class Action Finder

A skill that scans your email for class action settlements, scores each notice for legitimacy, and remembers what you've filed and been paid — so you don't leave money on the table.

It's just a plain-Markdown `SKILL.md` plus a few reference guides — nothing tool-specific baked into the logic. Today you run it on Claude (**Claude Code** or **Claude.ai** — web, desktop, mobile); because it's ordinary written instructions, any other agent that supports the skill format can read it too. Once installed it works **globally** — in any folder or session. No terminal? See [Using it on Claude.ai](#using-it-on-claudeai) below.

> **Which email providers work?** It reads whatever email account you connect to Claude. **Gmail is fully supported and best-tested.** Connect a different provider (where Claude offers an integration) and it adapts its searches — with a couple of caveats. See [Using a different email provider](#using-a-different-email-provider).

## Two jobs, one skill

The skill does two things that feed each other:

1. **Find** — scans your inbox, spam, and promotions for settlement notices and builds a styled HTML report: what you can claim now, what to watch, what expired, and what looks like phishing.
2. **Remember** — keeps a private record of what you've filed and been paid. The scan reads that record, so each report already knows what you've handled and stops nagging you about it.

Because the report is just a rendered view of *(email findings + your record)*, anything you tell it — *"I already filed that one"* — is saved permanently, shows up in the current report right away, and carries into every future scan. That's the whole point of it being one skill instead of two disconnected ones.

## Quick start (Claude Code)

**Already have Claude Code?** Skip to [step 2](#2-connect-your-email). `install.sh` only adds this one skill; it doesn't touch anything else in `~/.claude/skills/`.

### 1. Install Claude Code

Skip if `claude` already works in your terminal (`claude --version`).

```bash
npm install -g @anthropic-ai/claude-code
```

### 2. Connect your email

It reads your email via Claude's MCP integration (read-only — it never stores or transmits your email data).

1. Go to [claude.ai](https://claude.ai) → **Settings → Integrations**
2. Connect **Gmail** and authorize read access

### 3. Clone and install

```bash
git clone https://github.com/yingying-chu/yy-class-action-finder.git
cd yy-class-action-finder
./install.sh
```

Restart Claude Code, then run your first scan:

```
/class-action-finder
```

## Using it on Claude.ai

No terminal, no git, no cloning. Claude.ai (web, desktop, mobile) supports the same Skills format through **Settings → Capabilities → Skills**.

1. **Download the skill** — click to download directly, no build step:
   [class-action-finder.skill](https://raw.githubusercontent.com/yingying-chu/yy-class-action-finder/main/dist/class-action-finder.skill)
2. **Upload it** at **Settings → Capabilities → Skills → Upload skill**
3. **Connect your email** at **Settings → Integrations** (same as above)
4. **Use it** — just talk to Claude: *"scan my email for class action settlements"* or *"I filed my ExampleApp claim"*

One difference from Claude Code: there's no local `output/` folder on Claude.ai, so the HTML report comes back to you **in the conversation** as a downloadable file instead of being written to disk.

## What it does

### Find: scan your email

```
/class-action-finder              # last 12 months (default)
/class-action-finder 6 months     # last 6 months
/class-action-finder 2024         # all of 2024
```

Or just say: *"scan my email for class action settlements"*, *"am I owed any settlement money?"*, *"did I miss any claim deadlines?"*

The report splits everything into five sections:

| Section | What's in it |
|---|---|
| **Active Claims** | Open claim windows with deadlines — soonest first |
| **Watch List** | Lawsuits announced, claim form not open yet |
| **Expired** | Deadlines passed — for reference |
| **Already Filed** | Cross-referenced from your record + payment emails |
| **Phishing Alerts** | Emails scoring below 40% — do not click |

It's saved to the skill's own `output/` folder — never your Desktop or Documents:

```
~/.claude/skills/class-action-finder/output/class-action-report-YYYY-MM-DD.html
```

After a scan, Claude gives you a short summary in chat:

```
Report saved: ~/.claude/skills/class-action-finder/output/class-action-report-2026-05-12.html

  3 actionable claims found
  Potential payout: $125 – $10,200+
  Most urgent: ExampleApp — deadline Jul 2, 2026 (51 days)
  2 emails surfaced from spam
  0 phishing alerts
```

### Remember: record what you've filed

Just tell Claude in plain language — no separate command:

- *"I already filed the ExampleApp one"*
- *"I got a $47 check from SampleHealth Group"*
- *"add SampleVoice Privacy to my watch list"*
- *"show me all my filed claims"*

When you record a filing or payout that's in your latest report, the skill offers to **update that report on the spot** — no need to re-scan your email. And because it's saved to your record, every future scan remembers it too. Your record lives in `~/.claude/class-action-tracker.json`, local to your machine, never committed to this repo.

### Phishing scoring

Every settlement email gets a confidence score before it reaches you:

| Score | Level | Meaning |
|---|---|---|
| 85–100% | 🟢 High confidence | Case verified in news/court records, known admin domain |
| 60–84% | 🟡 Likely legitimate | Most signals positive, limited verification |
| 40–59% | 🟠 Uncertain | Verify manually before acting |
| < 40% | 🔴 Phishing risk | Do not visit any links — report as phishing |

Green flags: sender is a known administrator (Epiq, Kroll, JND), case appears in news or PACER, no payment requested, court case number present. Red flags: requests a processing fee, asks for SSN or bank account, unverifiable case name, random sender domain.

Anything scoring 🔴 goes in its own red-flagged section, and every report ends with a "What To Do Next" panel sorted by soonest deadline:

## Using a different email provider

It isn't hard-wired to Gmail — it searches whichever email account you've connected and adapts to that provider's search syntax. But providers aren't all equal:

- **Gmail — fully supported.** The searches are tuned for Gmail, including dedicated sweeps of your **spam and promotions folders**, where a lot of real settlement notices quietly land. The most complete experience.
- **Another provider Claude offers an integration for (e.g. Outlook).** Connect it the same way (**Settings → Integrations**) and it translates its searches into that provider's syntax — no forwarding, no separate Gmail account. Caveat: Gmail-specific folders like *spam* and *promotions* may have no equivalent, so a junk-filed notice could be missed. When that happens, the report header says so.
- **A provider with no Claude integration yet.** Claude can only read mail it can connect to. If there's no integration for your provider, it can't reach that inbox — a limit of which integrations exist, not the skill.

Bottom line: connect the email account you actually use. Gmail gets you everything; another supported provider gets you the core scan with any gaps flagged in the report.

## Run it automatically (scheduled scans)

You don't have to remember to run this. Because it's triggered by plain language, **any agent that can run on a schedule can run it for you** — Claude Code routines/cron, a scheduled task, or any agent framework that supports the skill format and a timer. Point the schedule at a prompt like *"scan my email for class action settlements from the last 30 days"* and it runs unattended.

Before you rely on that:

- **Weekly beats daily.** Notices trickle in and deadlines are weeks or months out, so a daily scan mostly produces empty reports. Once a week (or monthly) catches everything with far less noise.
- **Confirm the scheduled run can reach your mail.** The big one: it needs your email integration connected *and authorized in the environment where the schedule runs*. Interactive auth doesn't always carry into a background run — **do one manual run inside the scheduled setup first** to confirm it can read your inbox, then automate.
- **Send yourself the result.** A report nobody opens is a scan that didn't happen — use your scheduler's completion notification (push/email).
- **Keep your record current.** Tell the skill what you've filed so each weekly report stays focused on what's genuinely new.

## Privacy

- Reads your email through your provider's search API (read-only) via Claude's MCP integration
- No email content is stored anywhere by this skill
- Generated reports stay in `~/.claude/skills/class-action-finder/output/` — local, not synced, not committed
- Your claim record (`~/.claude/class-action-tracker.json`) is local to your machine and not synced
- Settlement websites are fetched to verify deadlines — only the claim URL is visited, not your personal data

## Fork it, make it yours

It's just one `SKILL.md` and a few reference guides — easy to fork and bend to your needs. **Please do.** Some ideas:

- **Add first-class support for your email provider.** It's already provider-adaptive (see [Step 4 in SKILL.md](skills/class-action-finder/SKILL.md)); if you use Outlook, Proton, Fastmail, etc., tune the searches for it and send the improvement back.
- **Tweak the phishing scoring** in [`phishing-guide.md`](skills/class-action-finder/references/phishing-guide.md) — add administrator domains you trust, or adjust the weights.
- **Restyle the report.** [`report-template.md`](skills/class-action-finder/references/report-template.md) and Step 9 define the HTML.
- **Localize it** for settlements and claim-notice conventions in your country.

To contribute back: fork, make your change, and open a pull request — or just open an issue. No contribution is too small, and adapting it purely for yourself is completely fine too.
